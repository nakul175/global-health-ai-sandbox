# API and Event Contracts

This contract baseline defines how independent clients, services and workers exchange validated commands and events. The normative files are contracts/openapi.json, command_registry.json, events.schema.json, errors.json, semantic_rules.json and protocol_rules.json. Version 1.1 replaces open resource payloads with a closed union for the first workflows.

## Contract coverage
OpenAPI 3.1.1 describes 53 paths and 70 named schemas. The seven writable payload kinds are InstitutionApplication, Programme, Study, AccessRequest, Import, SafetyConcern and MembershipInvitation. ORG owns institution and programme payloads; WFL owns studies, DAC access requests, ING imports, SAF safety concerns and IAM invitations. DEM health-needs intake retains its separate source scope. Every nested object rejects additional fields. A schema kind must match the endpoint domain. Arrays have declared bounds and uniqueness where required; UUIDs, hashes, lengths, enums and required fields are machine-readable.
All 40 source command inputs are closed. Commands for later features are forward interfaces and remain disabled until their owning slice is implemented and accepted. ResourceSummary is a safe metadata projection; a detailed read or edit is unavailable if its domain schema has not been activated. The capabilities endpoint advertises only operationally accepted commands and payloads. It must never imply that a schema file constitutes an implemented service.

## Transport and identity
Use HTTPS outside loopback development. JSON is UTF-8 with a maximum one MiB body. Reject duplicate property names, unknown fields, non-finite numbers, invalid formats and silent type coercion. Timestamps use UTC RFC3339 with Z and at most microsecond precision. UUIDs do not confer authority. The authenticated subject is bound to a server-issued context; no caller supplies a trusted tenant identifier in a business payload.
Browser authentication uses OIDC authorization code with PKCE and an HttpOnly, Secure, SameSite session cookie. Cookie-based writes require the declared CSRF header and an allowed origin. Service calls use scoped short-lived access tokens with the correct issuer and audience. Verify signature, algorithm allowlist, expiry, not-before and assurance. Check current membership and restrictions independently of a token's unexpired signature.
X-Context-Id is mandatory on protected regional requests. Context is one active membership or bounded applicant/workload delegation; permissions from other contexts are not merged. Return 401 for absent authentication. A hidden or nonexistent record returns the same 404 E_UNAVAILABLE envelope. Field errors must identify allowed schema paths without reflecting protected values.

## Requests and responses
Command requests contain context and payload. A create command has null object_ref and expected_version; a change to an existing aggregate requires both a UUID and a positive expected_version. The per-command schema determines this distinction. A committed command returns CommandReceipt; asynchronous acceptance returns 202 only after durable intent has committed. The receipt identifies the object, version, state, correlation, commit time and optional job. Acceptance is not completion.
Resource POST returns 201 with a Resource. PATCH changes the title and/or replaces the entire supplied closed payload. Omitted properties remain unchanged; null is accepted only where expressly permitted. Changing a frozen record requires a successor. GET and successful PATCH expose a strong ETag of the form "vN". PATCH requires If-Match; missing preconditions return 428, stale versions return 409. No wildcard overwrite is allowed.
The Error envelope always includes code, safe message, correlation_id, retryable and a fields array. errors.json maps each code to status. Validation and semantic failures use 422; unsupported media 415; oversize bodies 413; rate limits 429; transient dependency failures 503. Upload expiry uses 410 only after permission to discover that upload is established. Retry-After is supplied for 429 and retryable contention or dependency responses.

## Semantic constraints
Schema validation is followed by current authorization and domain validation. Grant validity must have a positive interval. Approved scope is a subset of both the request and the approver's authority, including purpose, recipients, fields, cohort, region and time. A reference resolves to its exact permitted object kind and version. For a foreign study, the custodian uses its own verified external-reference record.
Import accepted, rejected and quarantined counts must sum to source count. A metric observation distinguishes observed, missing, suppressed and invalid. An observed ratio has denominator above zero, numerator within denominator and value matching the ratio within 1e-9. A missing value is null with a reason; zero is a valid measured value. Review decisions bind a snapshot digest, assigned role and a verified person distinct from the author.

## Idempotency and concurrency
Idempotency-Key is 16 to 128 characters from letters, digits, underscore and hyphen. Scope is tenant, principal and command or resource operation. The digest is SHA256 over RFC8785 canonical JSON containing method, route, context and payload. Reusing a key with a different digest returns 409. The runtime must implement RFC8785, not approximate it with ordinary JSON serialization.
In one transaction, recheck current rights, lock the target and any budget row, compare the version, persist business state, receipt, audit and outbox, then commit. A duplicate request waits at most two seconds for the first committer; unresolved contention returns 409 with Retry-After 1. Authorize again before returning an existing receipt. Receipts live for seven days; durable source-event and business uniqueness prevent duplicates after receipt expiry.
Use keyset pagination ordered by created_at descending then id descending. Default page size is 50 and maximum is 200. The authenticated cursor includes version, tenant, principal, scope revision, filter digest, last tuple, as-of timestamp and a fifteen-minute expiry. Invalid cursors return 422. Changed authorization invalidates continuation. Do not emit totals or facets over undiscoverable records. No offset pagination or arbitrary sort expressions are accepted in the first workflow.

## Resumable upload protocol
| Operation | Exact contract |
| Create | POST /v1/uploads with target resource, grant, purpose, safe display name, media type, total bytes and full SHA256; 201 UploadSession |
| Put part | PUT /v1/uploads/{id}/parts/{index}, octet-stream body, exact Content-Length and X-Part-SHA256; 200 acknowledged UploadPart |
| Recover | GET /v1/uploads/{id} returns acknowledged parts and current state after current rights check |
| Finalise | POST /v1/uploads/{id}/finalise with expected version, full SHA256 and part count; 202 verifying session after durable job commit |
| Abort | POST /v1/uploads/{id}/abort with expected version and reason; 200 terminal intent; concurrent finalisation is serialized |
An object contains 1 to 10,737,418,240 bytes. Chunks are 8,388,608 bytes, except the last chunk; there are at most 1,280 chunks, indexed from zero. Offset equals index multiplied by chunk size. The last length equals total minus its offset. Allow four simultaneous parts per session and enforce a tenant-wide quota in admission policy. A session expires seventy-two hours after creation; activity does not extend it.
The application gateway checks the active owner, grant, purpose, region, hold state, session expiry, index and length on each PUT. It computes the part hash from received bytes before acknowledging a durable object and database part record. Unacknowledged orphan bytes can be collected. The same index and digest returns the prior acknowledgement; a different digest returns 409 E_PART_CONFLICT. Parts may arrive out of order. No content encoding or arbitrary byte overlap is accepted.
After a lost response, GET the session and resend only missing parts. Re-selecting a local file requires matching length and full digest before reuse. Parts do not increment the control version; finalise and abort do. A failed or expired session cannot be reopened. Create a new session after correcting the problem. A checksum mismatch never counts as a stored part.
Finalisation takes the session row lock used by part insertion and abort. It requires every unique part and exact total length, changes state to verifying and commits a job. No later part is accepted. The worker checks current rights, recomputes the assembled whole-object hash and writes an immutable quarantine artifact. Scan and custody release are separate gates before any preview, search, AI retrieval, execution or export. A worker retry cannot publish content from an aborted or rights-revoked upload. The terminal state and cleanup proof remain auditable.
The default browser mode does not persist protected media offline. A managed offline client requires encrypted storage, a device-bound key, bounded cache quota and a locally enforced authorization lease; storage encryption is not permission to retain indefinitely. On lost keys, clear unreadable cache and require a fresh authorized session. UI recovery must distinguish local bytes, server-acknowledged parts, verification and actual availability.

## Event delivery and compatibility
The event schema has 40 command-committed variants and four upload or support variants. Every envelope includes schema version, event ID, type, tenant, aggregate and version, aggregate sequence, actor, occurrence time, correlation and causation. Payloads carry receipt/state/job or typed upload outcomes and references; they do not carry patient content, secrets or sealed labels.
Outbox delivery is at least once. Consumers deduplicate by consumer ID and event ID in the same transaction as their state effect. Order is per aggregate sequence; wall-clock order is insufficient. Park sequence gaps, reconcile with the authority and quarantine invalid schemas. Retries occur after 1, 5, 30, 120 and 600 seconds; exhausted work enters durable dead-letter state with an alert. Replay retains the original event ID and requires current authority.
Transmitted, acknowledged and processed are distinct states. An HTTP success from an external system establishes only its documented acknowledgement level. Contract changes require compatibility review, explicit versioning and test fixtures. Strict consumers require coordinated additive changes; new fields are not silently accepted.
